# CALISTHENICS CHALLENGE

منصة تدريب كاليسثنكس ذكية باشتراك مدفوع: استبانة واختبارات قدرات ← تحليل ← دفع وتفعيل من الإدارة ← برنامج مخصص لكل مشترك ← تمارين يومية بشرح عربي ← اختبارات دورية ورسوم بيانية ← إيقاف تلقائي عند انتهاء الاشتراك.

**التقنيات:** Next.js 15 (App Router) + Supabase (PostgreSQL + المصادقة + التخزين) + Tailwind CSS. واجهة عربية بالكامل RTL ومصممة للجوال أولاً.

---

## دليل التشغيل خطوة بخطوة (بدون خبرة برمجية)

ستحتاج إلى ثلاثة حسابات مجانية: **GitHub** و**Supabase** و**Vercel**.

### 1) إنشاء قاعدة البيانات على Supabase
1. ادخل إلى <https://supabase.com> ← **New project**. اختر اسماً وكلمة مرور قوية لقاعدة البيانات، والمنطقة الأقرب (مثل Frankfurt أو Mumbai).
2. من القائمة الجانبية افتح **SQL Editor** ← **New query**:
   - انسخ محتوى الملف `supabase/migrations/0001_init.sql` كاملاً، والصقه، ثم اضغط **Run**.
   - افتح استعلاماً جديداً، وانسخ محتوى `supabase/seed.sql` (مكتبة 74 تمريناً بالشرح العربي)، ثم **Run**.
3. **Authentication ← Sign In / Providers ← Email**: أوقف خيار **Allow new users to sign up** (الحسابات يُنشئها المدير فقط).
4. **Project Settings ← API**: انسخ القيم الثلاث:
   - `Project URL`
   - `anon public` key
   - `service_role` key (سري — لا تشاركه أبداً)

### 2) رفع المشروع إلى GitHub
1. أنشئ مستودعاً جديداً **خاصاً (Private)** على GitHub.
2. ارفع ملفات المشروع إليه (زر **Add file ← Upload files** يكفي، اسحب كل محتويات المجلد).

### 3) النشر على Vercel
1. ادخل إلى <https://vercel.com> بحساب GitHub ← **Add New ← Project** ← اختر المستودع.
2. في **Environment Variables** أضف:

| المتغير | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
| `INITIAL_ADMIN_USERNAME` | اسم مستخدم المدير، مثل `admin` (أحرف إنجليزية صغيرة/أرقام) |
| `INITIAL_ADMIN_PASSWORD` | كلمة مرور قوية (10 أحرف على الأقل) |
| `APP_TIMEZONE` | `Asia/Muscat` (اختياري) |

3. اضغط **Deploy**. بعد دقيقتين تقريباً تحصل على رابط الموقع.

### 4) أول دخول للمدير
1. افتح `رابط-موقعك/login` — يُنشأ حساب المدير الرئيسي تلقائياً من المتغيرين السابقين (مرة واحدة فقط).
2. ادخل به، ثم غيّر كلمة المرور من **حسابي**.
3. ارجع إلى Vercel ← Settings ← Environment Variables واحذف `INITIAL_ADMIN_USERNAME` و`INITIAL_ADMIN_PASSWORD`.
4. من **الإعدادات** في لوحة المدير: راجع السعر (10 ر.ع)، رقم واتساب (98836695)، واكتب **تعليمات الدفع** الفعلية (رقم الحساب البنكي/المحفظة).

> بديل: يمكن إنشاء المدير من الطرفية: `ADMIN_USERNAME=admin ADMIN_PASSWORD='...' npm run create-admin` مع متغيرات Supabase.

### 5) ربط نطاق خاص (اختياري)
Vercel ← Project ← Settings ← Domains ← أضف نطاقك واتبع التعليمات.

## كيف يعمل النظام يومياً

1. العميل يفتح الموقع ← **ابدأ التحدي** ← يملأ الاستبانة (10 مراحل مع مؤشر اكتمال، وتُحفظ تلقائياً على جهازه).
2. النظام يحلل البيانات فوراً ويعرض ملخصاً، والسعر، وتعليمات الدفع.
3. العميل يرفع الإيصال أو يكتب مرجع التحويل ← تصبح الحالة **«بانتظار تأكيد الدفع»** ← يضغط زر واتساب برسالة جاهزة.
4. المدير: **الطلبات والاستبانات ← طلبات دفع جديدة** ← يفتح الطلب، يرى الإيصال ومعاينة البرنامج والتنبيهات الصحية ← **قبول وتفعيل** (يحدد المدة: 7/14/28/30/60/90 أو مخصصة).
5. بضغطة واحدة يُنشأ: الحساب + الاشتراك + **البرنامج المخصص** + الاختبار الأول. تظهر بيانات الدخول مع زر لإرسالها للعميل عبر واتساب.
6. العميل يدخل، يغيّر كلمة المرور المؤقتة، ويبدأ تمارينه اليومية.
7. عند انتهاء المدة يتوقف الوصول **تلقائياً** (يُتحقق منه في قاعدة البيانات نفسها) وتظهر له صفحة التجديد. التمديد يتم من صفحة المستخدم دون إنشاء حساب جديد، وكل تقدمه محفوظ.

## محرك البرامج المخصصة

موجود في `lib/engine/` ومستقل تماماً ويمكن اختباره:

- **تحديد المستوى الحقيقي** لكل نمط حركي (دفع، سحب، رجلين، جذع) من نتائج الاختبارات، مع احترام إجابة «لا أستطيع أداء التمرين».
- **سلّم تدرج** لكل نمط (مثل: الضغط على الحائط ← المائل ← على الركبتين ← الكامل ← الماسة ← …). يختار المحرك التمرين المناسب لمستواك وأدواتك.
- **نطاقات التكرار والراحة حسب الهدف** (ACSM/NSCA): قوة، عضلات، حرق، لياقة، شد، مهارات، مختلط. وتخصيص التكرارات من نتيجتك الفعلية (50-70% من أقصى عدد).
- **ملاءمة مدة الجلسة لوقتك**: من 10 دقائق (دوائر قصيرة) إلى أكثر من 45 دقيقة؛ يُحسب الوقت المتوقع لكل يوم.
- **التدرج والاستشفاء**: +10% أسبوعياً، أسبوع تخفيف كل 4 أسابيع، نسخة أصعب في الكتلة التالية، أيام راحة موزعة، وحد لجلسات القوة حسب المستوى (أيام إضافية تتحول إلى استشفاء نشط/لياقة).
- **السلامة**: استبعاد التمارين التي تضغط على مناطق الإصابة أو الألم، واستبدال القفز بتمارين منخفضة التأثير عند الحاجة (وزن مرتفع، عمر 60+، ركبة/كاحل/ظهر، حالات صحية)، مع تنبيه التقييم الطبي.
- **بدائل** أسهل وأصعب لكل تمرين، و**اختبار إعادة تقييم كل أسبوعين**.
- إعادة البناء بعد إعادة التقييم تنقل المستخدم إلى **مرحلة أعلى** تلقائياً.
- التمارين التي يضيفها المدير من لوحة التحكم يستخدمها المحرك تلقائياً (حسب النمط والصعوبة والأدوات والقيود).

المراجع العلمية معروضة للمستخدمين في صفحة `/methodology`.

## الفيديوهات التعليمية

المكتبة تحتوي 74 تمريناً بشرح عربي نصي كامل (الوضعية، الخطوات، التنفس، الأخطاء الشائعة، تجنب الإصابة، التدرج). **لا توجد فيديوهات وهمية**: إلى حين إضافة الفيديو يظهر رسم توضيحي مؤقت مع الشرح النصي.

لإضافة فيديو: **لوحة المدير ← التمارين والفيديو ←** اختر التمرين ← أضف رابط YouTube أو ارفع ملفاً (mp4/webm/mov). الحد الافتراضي لحجم الملف في خطة Supabase المجانية 50 ميغابايت (يمكن رفعه من Storage settings)، وفيديوهات 20-60 ثانية عادة أقل بكثير.

## النسخ الاحتياطي

- **فوري:** لوحة المدير ← الإعدادات ← «تنزيل نسخة احتياطية الآن» (JSON بكل الجداول).
- **يومي تلقائي (مجاني):** الملف `.github/workflows/backup.yml` جاهز. في GitHub ← Settings ← Secrets ← Actions أضف السر `SUPABASE_DB_URL` (من Supabase ← Connect ← Session pooler URI مع كلمة مرور قاعدة البيانات). ستُحفظ نسخة يومية لمدة 30 يوماً.
- خطة Supabase Pro توفر أيضاً نسخاً يومية تلقائية من لوحة Supabase.

## الأمان

- كلمات المرور مشفّرة بواسطة Supabase Auth (bcrypt) ولا تُخزن نصاً عادياً أبداً.
- **Row Level Security** على كل الجداول: كل مستخدم يرى بياناته فقط، ولا يستطيع تعديل بيانات غيره أو منح نفسه اشتراكاً أو صلاحيات.
- **سريان الاشتراك يُتحقق منه داخل قاعدة البيانات** (`has_active_access`)، فلا يمكن تجاوزه من المتصفح. ينتهي الوصول تلقائياً لحظة انتهاء المدة.
- صفحات المدير محمية بالدور والصلاحيات، والمشرفون الفرعيون يرون الأقسام المسموحة لهم فقط (المستخدمون، الاشتراكات، الاستبانات، البرامج، المكتبة، الإحصائيات، الإعدادات).
- مفتاح `service_role` يُستخدم في الخادم فقط ولا يصل إلى المتصفح. بيانات المدير الأولية من متغيرات البيئة وليست في الكود.
- الإيصالات في تخزين خاص لا يصل إليه إلا المدير عبر روابط مؤقتة (10 دقائق).
- سجل عمليات إدارية (من فعّل/مدّد/حذف ومتى).

## للمطورين

```bash
npm install
cp .env.example .env.local   # ثم املأ القيم
npm run dev                  # http://localhost:3000
npm run build && npm start
```

| الأمر | الوظيفة |
|---|---|
| `npm run test:engine` | اختبارات محرك البرامج (12 اختباراً: صحة الخطط، الأدوات، الإصابات، المدة، التدرج، التنوع بين المستخدمين) |
| `npm run test:db` | اختبار تكامل يُنشئ برنامجاً حقيقياً في PostgreSQL (يحتاج قاعدة اختبار) |
| `psql -f supabase/tests/supabase_stub.sql -f supabase/migrations/0001_init.sql -f supabase/seed.sql -f supabase/tests/rls_test.sql` | اختبارات الصلاحيات وانتهاء الاشتراك على قاعدة PostgreSQL محلية فارغة |
| `npm run seed:generate` | إعادة توليد `seed.sql` بعد تعديل `lib/engine/library.ts` |

### هيكل المشروع
```
app/                 الصفحات (/, /start, /subscribe, /login, /app/*, /admin/*)
  start/actions.ts   حفظ الاستبانة وتحليلها
  app/actions.ts     تسجيل التمارين والتقييمات وكلمة المرور
  admin/_actions/    كل عمليات المدير (تفعيل، تمديد، برامج، مكتبة، صلاحيات)
components/          مكونات الواجهة (الاستبانة، مشغّل التمرين، الرسوم البيانية…)
lib/engine/          محرك التحليل وبناء البرامج + مكتبة التمارين
lib/                 المصادقة، Supabase، أدوات مساعدة
supabase/            الهجرة، البذور، اختبارات RLS
scripts/             إنشاء مدير، توليد البذور
```

### ما تم اختباره
- محرك البرامج: 12 اختباراً ناجحاً على ملفات مستخدمين متنوعة.
- قاعدة البيانات: الهجرة (قابلة لإعادة التشغيل)، البذور، واختبارات RLS الكاملة على PostgreSQL 16 (المشترك النشط/المنتهي/الموقوف، المشرف الفرعي، المدير الرئيسي، الزائر، منع الانتحال ورفع الصلاحيات، التمديد يعيد الوصول، الإحصائيات).
- تكامل إنشاء البرنامج الفعلي مع مخطط قاعدة البيانات.
- فحص الأنواع لكل ملفات التطبيق.
